## P0 — quebrado ou inaceitável em produção

### P0-1. Tailwind carrega 2× (CDN + integração Astro)
- **Arquivo:** [`src/layouts/BaseLayout.astro:73`](../src/layouts/BaseLayout.astro#L73)
- **Problema:** `<script src="https://cdn.tailwindcss.com">` carregado em todas as páginas, **junto** com `@astrojs/tailwind` que já gera o CSS pré-compilado. Tailwind explicitamente diz que o CDN não deve ir pra produção (sem purge, sem custom config, 300KB+ de JS).
- **Fix:** remover linha do `<script>`. A integração já cobre tudo. Esforço: 1 min.

### P0-2. GSAP, Lenis, Iconify via CDN (deps npm já instaladas)
- **Arquivo:** [`src/layouts/BaseLayout.astro:74-77`](../src/layouts/BaseLayout.astro#L74-L77)
- **Problema:** `package.json` já lista `gsap`, `lenis`, `iconify-icon` mas o site puxa de CDN externo. Custo: 4 round-trips DNS/TLS extra, sem CSP estrita, sem garantia de versão.
- **Fix:** importar como módulo nos componentes que usam. Esforço: 15 min (revisar onde GSAP/Lenis são chamados).

### P0-3. Formulário de contato quebrado em prod
- **Arquivo:** [`src/pages/contato.astro:13`](../src/pages/contato.astro#L13)
- **Problema:** `WEB3FORMS_KEY = 'COLE-SUA-CHAVE-WEB3FORMS-AQUI'`. Se o site for ao ar agora, o form não envia nada.
- **Fix:** mover pra `.env` + `import.meta.env.PUBLIC_WEB3FORMS_KEY`, criar `.env.example`, instrução no PILOTAR.md. Esforço: 10 min.

### P0-4. Rota `[slug]` colide com `/sobre`
- **Arquivos:** [`src/pages/[slug].astro`](../src/pages/[slug].astro), [`src/content/pages/sobre.md`](../src/content/pages/sobre.md), [`src/pages/sobre.astro`](../src/pages/sobre.astro)
- **Problema:** build emite warn — Astro escolhe `sobre.astro` mas `sobre.md` fica órfão (e tem **copy diferente** da página oficial → confusão futura).
- **Fix:** decidir: **(a)** apagar `sobre.md` (sobre.astro é a página real) ou **(b)** filtrar slugs já cobertos em `getStaticPaths`. Recomendo (a). Esforço: 1 min. **⚠️ apaga conteúdo Markdown — preciso da sua autorização.**

### P0-5. `global.css` referencia token inexistente
- **Arquivo:** [`src/styles/global.css:13`](../src/styles/global.css#L13)
- **Problema:** `background: var(--bg-white)` — esse token **não existe** em `tokens.css`. Body cai pra fundo padrão do browser (geralmente branco, mas instável).
- **Fix:** trocar por `var(--paper)` (off-white #F5F5F7, conforme DS). Esforço: 1 min.

## P1 — Estrutural / Design System

### P1-7. Design System bifurcado — duas verdades em conflito
- **Sintoma:** [`src/styles/tokens.css`](../src/styles/tokens.css) define tokens canônicos (`--ink`, `--paper`, `--white`, `--yellow`). Mas **8 de 10 páginas** ([cases](../src/pages/cases.astro), [contato](../src/pages/contato.astro), [index](../src/pages/index.astro), [insights](../src/pages/insights.astro), [metodo](../src/pages/metodo.astro), [pep](../src/pages/pep.astro), [processos](../src/pages/processos.astro), [sobre](../src/pages/sobre.astro)) abrem `<style is:global>` com `:root { --primary, --accent, --paper-lifted, --ink-soft, --hairline, --radius-btn… }` redefinindo tudo.
- **Impacto:** mudar uma cor em `tokens.css` **não muda o site**. O DS está documentado mas não vinculado. Cada página é uma ilha.
- **Fix:** consolidar todos os tokens em `tokens.css`, deletar os `:root` locais, padronizar nomes. Esforço: 1-2h, alto risco visual — recomendo branch dedicada.

### P1-8. Classes `ds-h1/h2/body/mono` não estão em `global.css`
- **Arquivo:** [`src/styles/global.css`](../src/styles/global.css) (só tem reset + Tailwind base)
- **Problema:** as classes do DS são definidas inline em cada página. A página [`[slug].astro:20-22`](../src/pages/[slug].astro#L20-L22) usa `ds-h2` e `ds-mono` — e como ela **não** abre `:root` local nem importa classes, **os estilos só funcionam por sorte** (cascata Tailwind + heranças).
- **Fix:** mover `.ds-h1/h2/h3/h4/body/body-lg/body-sm/mono/eyebrow-dot` pra `global.css`. Esforço: 20 min. Agrupado com P1-7.

### P1-9. Google Fonts via CDN (vs `@fontsource` já instalado)
- **Arquivo:** [`BaseLayout.astro:65-70`](../src/layouts/BaseLayout.astro#L65-L70)
- **Problema:** já tem TODO no código. `@fontsource/inter`, `@fontsource/instrument-serif`, `@fontsource/jetbrains-mono` instalados mas não usados.
- **Fix:** importar em `global.css`, remover preconnect/link. Esforço: 15 min.

### P1-10. Nav sumida em mobile, sem hamburguer
- **Arquivo:** [`Nav.astro:32`](../src/components/Nav.astro#L32) — `class="hidden md:flex …"`
- **Problema:** em telas <768px o usuário só vê logo + CTA "Agendar diagnóstico". Não tem como navegar para Sobre/Método/Cases/Processo/PEP/Insights pelo header.
- **Fix:** adicionar botão hamburguer + drawer/sheet. Esforço: 30-45 min.

### P1-11. Footer com link morto `/#pricing`
- **Arquivo:** [`Footer.astro:28`](../src/components/Footer.astro#L28)
- **Problema:** "Planos" aponta pra `/#pricing` mas a âncora **não existe** em `index.astro`. Verifiquei: as âncoras `#about`, `#capabilities`, `#work`, `#values`, `#team` existem (✓). Só `#pricing` ficou órfã.
- **Fix:** decidir — apontar pra `/pep` (planos PEP), criar seção `#pricing` na home, ou remover do footer. Esforço: 1 min.
